# Route-test plan: INTERNET/TransferFundsOp

## 1. Successful fund transfer path through ValidateTransfer, CheckLimits, FraudCheck, and ExecuteTransfer to end.

Scenario: transfer_success

Coverage: route-ValidateTransfer, route-CheckLimits, route-FraudCheck, route-ExecuteTransfer, operation-flow, operation-step-injection

Inputs:
- Valid request XML containing source account, target account, amount, and valid session token

Collaborator setup:
- ValidateTransfer returns 0
- CheckLimits returns 0
- FraudCheck returns 0
- ExecuteTransfer returns 0

Expected outcome: Formatted success response XML containing transfer ID, status, and updated balances

Expected side effects:
- Database connection used to execute transfer stored procedure
- Transfer status set to PENDING or SUCCESS

Original path:
- ValidateTransfer → on0Do → CheckLimits
- CheckLimits → on0Do → FraudCheck
- FraudCheck → on0Do → ExecuteTransfer
- ExecuteTransfer → on0Do → end
